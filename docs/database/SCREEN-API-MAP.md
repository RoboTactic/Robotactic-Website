# خريطة الشاشات والجداول وواجهات API

الخريطة مبنية على `backend/database/schema.sql` والشاشات والبيانات الحالية في `frontend/src`. بيانات `frontend/src/data` كانت بيانات معاينة، ولا تستخدمها الشاشات المربوطة مصدرًا للسجلات.

## شاشات الزوار

| الشاشة/القسم | جدول البيانات | الحقول الأساسية | مسار API |
| --- | --- | --- | --- |
| الرئيسية: موعد الفعالية والموقع والتسجيل العام | `site_settings` | `event_start_at`, `event_end_at`, `event_location_ar/en`, `general_registration_url`, `official_email` | `GET /api/public/site-settings` |
| الرئيسية والمسابقات | `competitions` | الاسم والوصف والمتطلبات بالعربية والإنجليزية، الفئة، الجمهور، حجم الفريق، المواعيد، حالة/رابط التسجيل، الصورة، التمييز والترتيب | `GET /api/public/competitions`؛ الصفحة الرئيسية تعرض المميز فقط |
| الرئيسية والورش | `workshops` | الاسم والوصف باللغتين، المقدم، الصورة، `start_at/end_at`, السعة والمقاعد المتاحة، حالة/رابط التسجيل، التمييز | `GET /api/public/workshops`؛ الرئيسية تعرض المميز فقط |
| مباشر الآن والجدول الزمني | `timeline_events` | العنوان والوصف والمواعيد والمكان باللغتين | `GET /api/public/timeline-events`; الرئيسية تستخدم `?current=true` |
| معرض المشاريع | `projects`, `project_categories`, `project_members` | الاسم والوصف، النوع والفئة، الصورة، الفريق والقائد، الروابط والتقنيات والمرحلة، الأعضاء وروابطهم الاجتماعية | `GET /api/public/projects` |
| الإعلانات | `announcements` | العنوان والوصف باللغتين، الصورة، الرابط، نافذة النشر والحالة | `GET /api/public/announcements`؛ المنشور فقط وضمن نافذة الوقت |
| الرعاة والأسئلة الشائعة | `sponsors`, `faqs` | حقول الشعار/الاسم/الترتيب والنشاط؛ وحقول السؤال والجواب باللغتين والترتيب والنشاط | `GET /api/public/sponsors`, `GET /api/public/faqs`؛ الجداول والمسارات موجودة لكن لا توجد لهما شاشة حالية |
| عن الملتقى | نص ثابت حاليًا في `data/home.js` | لا جدول محتوى مقابل | لا يحتاج API حتى تقرر إدارته من لوحة التحكم |
| الفريق | الشاشة والبيانات فارغة | لا يوجد جدول لفريق التنظيم؛ `project_members` خاص بأعضاء المشاريع | يحتاج تحديد الحقول المطلوبة قبل إضافة جدول |

تستبعد مسارات الزوار سجلات الفرق والمشاركين ومستخدمي الإدارة. كما تعرض المسابقات والورش والمشاريع والإعلانات والفعاليات المنشورة فقط، وتعرض الرعاة والأسئلة النشطة فقط. تستجيب المسارات بغلاف `{ data: ... }`.

## لوحة التحكم

| القسم | الجداول | مسارات الإدارة |
| --- | --- | --- |
| المسابقات | `competitions` | `GET/POST /api/admin/competitions`, `GET/PATCH/DELETE /api/admin/competitions/:id` |
| فرق المسابقات | `competition_teams` | `GET/POST /api/admin/teams`, `GET/PATCH/DELETE /api/admin/teams/:id`; يدعم `?parent=<competition_id>` |
| الورش | `workshops` | `GET/POST /api/admin/workshops`, `GET/PATCH/DELETE /api/admin/workshops/:id` |
| المشاركون | `workshop_participants` | `GET/POST /api/admin/participants`, `GET/PATCH/DELETE /api/admin/participants/:id`; يدعم `?parent=<workshop_id>` |
| المشاريع وأعضاء المشروع | `projects`, `project_members` | CRUD على `/api/admin/projects`; الأعضاء قائمة `members` ضمن إنشاء/تعديل المشروع |
| الإعلانات | `announcements` | CRUD على `/api/admin/announcements` |
| حسابات الفريق وصلاحياته | `admin_users` | `GET/POST /api/admin/users`, `PATCH/DELETE /api/admin/users/:id`; لا تُعاد كلمة المرور أو بصمتها |

تُفرض الأدوار على الخادم: `super_admin` يدير كل الأقسام؛ `competition_manager` يدير المسابقات والفرق؛ `workshop_manager` يدير الورش والمشاركين. تُقرأ صلاحية الحساب النشط من قاعدة البيانات لكل طلب. بيانات الفرق والمشاركين شخصية، لذلك تظل خلف المصادقة والصلاحيات ولا تظهر للعامة.

## فجوات المطابقة والقرارات

1. بيانات API ثنائية اللغة، بينما نماذج المعاينة كانت تعرض نصًا واحدًا؛ الواجهات تختار الحقل الموافق للغة وتحتفظ باللغتين في الإدارة.
2. الجداول الزمنية تخزن `TIMESTAMPTZ`، لذلك تُحوّل مواعيد الورش وتُجمّع حسب التاريخ المحلي للمتصفح، ولا تستخدم عناوين الأيام الثابتة في بيانات التجربة.
3. النشر والتسجيل حالتان منفصلتان. العام يعرض `status = published`، ويُعرض رابط التسجيل فقط إن كانت الحالة `open` والرابط صالحًا.
4. حقول لوحة التحكم السابقة (`title`, `date`, `capacity`...) لم تطابق الأعمدة مباشرة؛ النماذج الجديدة تستخدم حقول المخطط وتتحقق منها طبقة الخدمة قبل SQL.
5. Google Forms لا ترسل الردود إلى PostgreSQL تلقائيًا. روابط المسابقات والورش تبقى خارجية؛ يمكن للفريق إدارة سجلات الفرق/المشاركين يدويًا من لوحة محمية، أو يُبنى تكامل منفصل عند اعتماده.
6. لا توجد حالة قبول/رفض أو مصدر تسجيل في جدولي الفرق والمشاركين. الشاشة لا تعرض هذه الحالات ولا تختلقها.
7. المخطط يخزن روابط الصور فقط. لا يوجد رفع ملفات، وخيارات رفع الصور القديمة لا تستخدمها لوحة التحكم.
8. الشاشة العامة للفريق التنظيمي، وشاشات إدارة الرعاة والأسئلة الشائعة والجدول والإعدادات غير موجودة حاليًا؛ المسارات العامة متاحة لكن إدارتها من اللوحة ليست ضمن الأقسام الحالية.
9. فئات المشاريع معرفة في `project_categories`؛ حقل الإدارة الحالي يقبل رقم الفئة. يلزم إنشاء سجل الفئة قبل ربطه بمشروع.

## التهيئة

الخادم يحتاج `DATABASE_URL` و`AUTH_TOKEN_SECRET` (32 بايت عشوائيًا على الأقل) في `backend/.env`، وقائمة `CORS_ORIGINS` للواجهة. أنشئ أول مستخدم `super_admin` بعد تطبيق `schema.sql` عبر `npm run admin:create` داخل `backend`. لا توجد حسابات أو كلمات مرور افتراضية. ردود التسجيل الخارجية لن تظهر في الجداول إلى أن يرسلها تكامل معتمد أو يدخلها مشرف مخول.

المصادقة متاحة عبر `POST /api/auth/login`, `GET /api/auth/session`, و`POST /api/auth/logout`. الجلسة كوكي `HttpOnly`, `SameSite=Strict` تنتهي بعد 8 ساعات، وتُشترط قيمة `Origin` موثوقة لكل تعديل. واجهات العامة لا تتضمن البريد أو الهاتف أو كلمات مرور حسابات الإدارة.
